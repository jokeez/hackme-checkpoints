## 🤔 Зачем это

Сейчас все блоки HackMe создаёт **одна нода**. Это просто, но значит, что приходится *доверять*
оператору: что он не изменит старый блок, баланс или количество выпущенных монет.

Этот репозиторий убирает необходимость доверять **в отношении прошлого**:

1. Раз в сутки нода делает **чекпоинт**: хеш последнего блока **и отпечаток всех балансов** в сети.
2. **Подписывает** его тем же ключом, которым подписывает блоки, и **публикует** здесь.
3. Хеш чекпоинта **закрепляется в Bitcoin** через OpenTimestamps.

После этого никто — включая оператора — не сможет незаметно изменить историю до этой точки:
живая цепь перестанет совпадать с этим репозиторием, а метка в Bitcoin доказывает, когда
чекпоинт существовал.

> **Одной фразой:** это публичная книга квитанций блокчейна HackMe, в которую можно только дописывать.

## ⚡ Проверка за минуту

Нужны [Go](https://go.dev/dl/) 1.26+ и git.

```bash
git clone https://github.com/jokeez/hackme-checkpoints
git clone https://github.com/jokeez/hackme
cd hackme
go run ./cmd/checkpoint verify \
  -dir ../hackme-checkpoints/checkpoints \
  -signer HMC-dfc143732a1fc3bc \
  -api https://hackme.tech/pool/api
```

Всё в порядке, если видите `ok: … checkpoints …` и `ok: … block hash(es) match …`.

Если появится `HISTORY CHANGED at height …` — живая цепь больше не совпадает с опубликованным.
Пожалуйста, [откройте issue](https://github.com/jokeez/hackme/issues).

Не хотите ничего запускать? Значок **verify** вверху — это GitHub, который публично
перепроверяет репозиторий при каждом изменении и раз в сутки сверяет его с живой цепью.

## 🧩 Как это работает

| Что фиксирует чекпоинт | Зачем |
|---|---|
| **Хеш блока на высоте** | Старые блоки нельзя подменить. |
| **Отпечаток состояния** (`state_hash`) | Балансы HMC / SUP / HMS и nonce всех аккаунтов, эскроу Dig/Hunt, счётчики выпуска и сжигания — балансы нельзя тихо поправить. |
| **Счётчики эмиссии** (`totals`) | Сколько HMC выпущено и сожжено — видно сразу. |
| **Ссылка на предыдущий чекпоинт** | Удаление или подмена старого ломает все следующие. |
| **Подпись** | Создать валидный чекпоинт может только ключ ноды, которая делает блоки. |
| **Метка Bitcoin** (`.ots`) | Доказывает время существования чекпоинта — задним числом не подделать. |

Суммы указаны в **units**: `1 HMC = 100 000 000 units`.

## ❓ Вопросы

**Это делает HackMe децентрализованным?** Нет. Блоки по-прежнему создаёт одна нода. Чекпоинты
защищают *прошлое* от незаметных изменений, но не меняют, кто делает *будущие* блоки.

**Оператор может просто перестать публиковать?** Да, и это тоже будет видно: пропущенный
ежедневный чекпоинт — сам по себе сигнал. Всё уже опубликованное остаётся проверяемым навсегда.

**Можно отредактировать или удалить опубликованный чекпоинт?** Не незаметно: каждый новый
чекпоинт ссылается на хеш предыдущего, у всех, кто клонировал репозиторий, остался оригинал,
а метка в Bitcoin доказывает, что и когда существовало.

**Могу ли я сам пересчитать `state_hash`?** По публичному API — нет, нужна полная копия
реестра. Это обязательство: при любом споре о балансах на высоте чекпоинта ответ должен дать
ровно этот хеш. Хеши блоков, подписи и связи вы можете проверить уже сегодня.

**Кто подписывает?** Ключ ноды `HMC-dfc143732a1fc3bc` — тот же, чья подпись стоит на каждом
блоке. Проверка отклоняет чекпоинты с любым другим ключом.
